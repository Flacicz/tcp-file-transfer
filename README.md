# TCP File Transfer

Учебный проект: консольные клиент и сервер для передачи файлов по TCP под Linux.
Язык — C11, сетевой API — системные POSIX-сокеты, сборка — CMake.

**Статус:** разработка ещё не начата. В репозитории есть стартовый `main.c`
и конфигурация CMake. Ниже описаны требования к первой версии и планируемый запуск.

## Учебная цель

На практике разобраться в следующих темах:

- создание сокетов, ожидание подключений и установление TCP-соединения;
- передача потока байтов и разработка простого протокола приложения;
- частичные чтения и записи, определение конца передачи и обработка обрыва;
- чтение и запись файлов порциями с ограниченным расходом памяти;
- обработка ошибок и управление временем жизни файлов и сокетов;
- сборка с предупреждениями компилятора и отладка с помощью GDB.

## Задача первой версии

Реализовать две отдельные программы — клиент и сервер.

1. Сервер запускается на указанном порту и ожидает подключения.
2. Клиент получает адрес сервера, порт и путь к исходному файлу из аргументов.
3. Клиент подключается, передаёт размер файла и его содержимое.
4. Сервер получает данные и сохраняет их в файл в указанном каталоге.
5. После полного получения и успешного завершения записи сервер подтверждает успех.
6. Клиент сообщает результат пользователю. Сервер ожидает следующего клиента.

Одно соединение используется для передачи одного файла. Сервер обслуживает
клиентов последовательно. Обе программы работают с небольшими порциями данных,
не загружая файл целиком в память.

### Сохранение файлов

- Каталог сохранения задаётся при запуске сервера и должен существовать.
- Сервер назначает каждому файлу уникальное имя с расширением `.bin`, например
  `received-000001.bin`. Существующие файлы не перезаписываются, в том числе после
  перезапуска сервера. Точный способ формирования имени будет выбран при реализации.
- Исходное имя и расширение клиент пока не передаёт. Содержимое сохраняется
  побайтово: `.bin` не означает преобразование формата или кодировки.
- При обнаруженной ошибке или обрыве передачи сервер закрывает и удаляет неполный
  файл. Ошибки записи, закрытия и удаления должны быть отражены в диагностике.
- Ошибка отдельной передачи не должна без необходимости останавливать сервер.
  Файлы и сокеты освобождаются на всех обрабатываемых путях завершения.

## Протокол обмена

Клиент отправляет размер, затем содержимое файла. Сервер отвечает одним байтом статуса.

```text
Клиент → сервер: [размер: 8 байтов][содержимое: N байтов]
Сервер → клиент: [статус: 1 байт]
```

- Размер — беззнаковое 64-битное число `N` в сетевом порядке байтов
  (big-endian, старший байт первым).
- Содержимое — ровно `N` исходных байтов. Для пустого файла `N = 0`.
- `0x00` — сервер полностью получил файл и успешно завершил его запись и закрытие.
- `0x01` — сервер сообщает об ошибке приёма или сохранения. При ошибке отправка
  этого статуса выполняется, если соединение ещё позволяет ответить.

Статус — числовое значение одного байта, а не текстовая строка.
Клиент считает передачу успешной только после получения `0x00` в ответ на полностью
отправленный файл. Отсутствие ответа означает, что успех не подтверждён: файл мог
быть сохранён, но ответ мог не дойти. Неизвестный статус считается ошибкой протокола.
Подтверждение не обещает сохранность данных при сбое питания.

TCP не сохраняет границы отдельных отправок. Одна операция чтения может получить
только часть поля размера или содержимого. Обе программы должны учитывать частичные
чтения и записи. Закрытие соединения до получения всех ожидаемых байтов означает
незавершённую передачу.

## Планируемый запуск

Приведённые команды описывают будущий интерфейс. Сейчас программ `server` и `client`
ещё нет. Инструкция сборки будет добавлена после настройки и проверки сборки в Linux.

```text
./server <порт> <каталог-сохранения>
./client <IPv4-адрес-сервера> <порт> <путь-к-файлу>
```

Для проверки на одном компьютере сервер и клиент запускаются в разных терминалах.
Например, при уже существующем каталоге `received`:

```text
./server 9000 ./received
./client 127.0.0.1 9000 ./photo.jpg
```

`127.0.0.1` — адрес локального компьютера. Для передачи между компьютерами клиенту
указывается IPv4-адрес машины с сервером. В первой версии используются числовые
IPv4-адреса.

## Границы первой версии

В первую версию не входят:

- одновременное обслуживание нескольких передач;
- возобновление передачи после обрыва;
- передача исходного имени файла и других метаданных;
- авторизация и шифрование;
- доменные имена, IPv6 и поддержка Windows-сокетов;
- графический интерфейс и сторонние сетевые библиотеки.

## Критерии готовности

- Пустой файл, бинарный файл и файл значительно больше буфера передаются без
  изменения содержимого. Результат проверяется через `cmp` или контрольные суммы.
- Успешная передача отличается от обрыва во время получения размера, содержимого
  и ожидания подтверждения. Неполный файл удаляется при обработке ошибки сервером.
- Некорректные аргументы и ошибки файловых операций дают понятную диагностику.
- Существующие файлы не перезаписываются.
- После успешных и неудачных передач сервер принимает новые подключения,
  а число его открытых дескрипторов не растёт.
- Автор может объяснить используемые системные вызовы и воспроизвести разобранные ошибки.

## Текущее состояние и ближайший шаг

Пока есть стартовый проект CMake с выводом `Hello, World!`.
Сетевая передача, обработка файлов и перечисленные проверки ещё не реализованы.

Ближайший шаг — минимальные сервер и клиент, которые устанавливают соединение
на одном компьютере и сообщают об этом в терминалах. Передачу данных добавим
после разбора установки соединения. Архитектура будет описываться по мере реализации.
